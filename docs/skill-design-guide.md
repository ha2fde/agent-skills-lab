# Skill 设计规范

## 命名与结构

名称使用小写英文、数字、连字符，长度不超过 64 字符；文件夹名与 frontmatter name 一致。
所有正式技能位于 skills/<name>/。可选资源包括 scripts/、references/、assets/。
历史技能的根目录脚本可保留；移动脚本时必须同步文档与脚本内相对路径。

SKILL.md 使用 YAML frontmatter，至少包含 name 和 description。默认只使用这两个字段。
description 说明任务、平台和触发请求；正文写执行步骤、分支、失败处理与验收。
把长资料放 references/，从 SKILL.md 直接链接。不要为每个客户端复制一套技能。

## 生命周期与版本

catalog.json 记录每个 Skill 的版本和验证状态。
采用语义化版本：修订说明为 patch；兼容新增为 minor；名称、输入或行为不兼容为 major。
结构检查通过不等于功能已实测。记录平台和版本范围；过时的版本结论执行前重新核对官方资料。
每次发布记录实际变更，不把规划项作为安装项。

## 检查

检查合法 YAML、唯一名称、资源存在、shell 语法及相对路径。
运行有副作用的脚本必须在适当测试环境中进行；不要在维护仓库时顺带修改真实设备。
发布前确认许可证与私密信息，并为成功与失败各留一条可复现记录。
