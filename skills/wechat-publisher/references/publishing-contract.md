# 公众号发布规范

## 内容与隐私

- 开头用具体矛盾、问题或可验证事实。重要结论和主图放前面，删掉同义反复、标题党和泛泛的 AI 套话。将编辑要求留在工作流，成文只写读者需要的信息。
- 用短段、清晰标题和轻量强调。技术稿保留必要术语、因果链与证据，编号引用连续并保留可读的来源地址。
- 公开稿以公共场景和公开资料为主。未经明确许可，不写作者的私人工作经历、公司、账号、设备、内部流程、凭据或未披露漏洞。复查截图、图例和示例里的标识符。

## 移动排版与插图

- 默认用自然、无底色的阅读表面，正文约 18px、行高 1.85、段间留白 20–24px。标题约 23px，核查汉字间距。蓝灰正文和标题、少量深金强调可作为起点，按主题调整且保持可读对比。普通段落、标题和强调文字使用文字颜色、留白和细分隔线。特定版式要求可使用明确设计的容器底色，配套检查该容器中的前景色。
- HTML 用简单结构、内联 CSS、自适应图像、可折行的长词、代码和 URL。静态风格读回只证明已检查的 HTML 属性，微信客户端深浅色效果以实看为准。
- 流程或架构图制作成独立可上传的图片。画清楚节点和连线，手机优先纵排，缩到约 390 CSS px 时仍能读清主要标签。正文解读图的结论，删掉逐节点转述。
- 封面负责吸引，正文图负责解释或举证。短稿通常一张主图就够；有证据或结构需求再加图。逐图检查信息重复、字体、元素密度、真实性、授权和隐私。
- 封面按 900×383 全幅构图，检查缩略图安全区。优先重排元素以保留已确认的文字和图像。裁切涉及已确认内容时先核对用户授权。上传真实 HTTPS 原图或实际字节，使用返回的微信素材 ID 和微信正文图 URL。上传失败时保持草稿写入暂停。

## 验收

- 图、文、标题和封面各自独立核对。编辑质量、隐私、构图和信息重复由 AI 逐项审看，程序只负责可判定的结构与一致性。
- 草稿写入与独立读回各自记录。实际手机预览与 API 读回分开报告。正式发布需要单独授权。
