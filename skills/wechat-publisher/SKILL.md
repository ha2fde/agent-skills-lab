# 微信公众号文章与草稿

执行规范版本 **wechat-editorial-v4**。先读 [发布规范](references/publishing-contract.md) 和 [验收清单](references/quality-checklist.md)。传图时读 [图片运行手册](references/image-upload-runbook.md)。事故记录和旧升级计划只作历史背景。

1. “写一篇公众号文章”默认包含成稿、封面、合适的配图、排版、保存到草稿和独立读回。用户限定为选题、大纲、聊天内预览、只改写文案或只配图时，按范围交付。草稿供用户自己审核，聊天中简报验收结果。正式发布须另有明确授权和相应能力。
2. 需要写入时先确认实际工具目录和 `wechat_connection_status`。新稿优先用 `wechat_prepare_and_save_draft`。要求保留已审定内容时，先用 `wechat_get_draft` 读取精确 ID、索引和最新 `content_hash`，工具支持时传 `changed_fields` 限定字段，并逐字段复制未授权修改的值，再用 `wechat_update_draft` 更新同一篇。只改元数据时原样传入正文 HTML。对照变更前后标题、封面、图片和正文；已确认并准备自行发布的文章保持原样。
3. 先做编辑与视觉审核，再传真实图片。每张正文图有独立价值，流程或架构用实际渲染的图，优先在手机上纵向阅读。保护私人信息，公开稿用公共材料或明确标注的合成示例。检查图片及正文是否泄露私人场景。
4. 执行保存后独立调用 `wechat_get_draft`。对比实际标题、封面、正文、图片顺序和引用、文字层级及内联样式。分别报告写入、读回、语义审核、微信手机实看；服务返回 `created` 不能替代 `readback_verified`，任何一项未执行就标为未检查。出现不一致或结果未知，保留草稿 ID，用同一请求编号对账，避免重复创建。
5. 仅在获授权的合成测试使用 `test_draft=true` 与 `【测试草稿·勿发布】` 前缀。只有服务登记来源、独立读回确认并精确匹配 ID 后，才调用 `wechat_delete_test_draft`。标题或历史记录本身不足以授权删除。

当前工具目录与服务状态分别核对。若工具描述仍要求显式保存而当前任务是默认交付，在调用时明确说明用户已把“写一篇公众号文章”设为存草稿的长期默认。遇到权限或必填参数不可用，说明具体阻碍。
