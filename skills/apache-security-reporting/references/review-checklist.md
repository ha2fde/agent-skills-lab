# Pre-delivery checklist (mandatory)

- [ ] Private recipient and subject correct; `[SECURITY]` prefix used for ASF email.
- [ ] **No confidential report metadata or project+finding associations in public repo**, including path, commit, branch, PR, changelog.
- [ ] One issue per email; no public issue, public PoC, or disclosure before authorization.
- [ ] Plain-text English; compact, technical, no decorative Markdown tables.
- [ ] Verified affected version and environment; runtime-tested vs source-reviewed clearly separated.
- [ ] Attacker privileges/prerequisites and violated trust boundary stated.
- [ ] Minimal steps and observed result; server-side confirmation if available.
- [ ] Negative controls only when material; no repetitive audit trail or file manifest.
- [ ] Impact limited to verified behavior; no untested admin/MFA/host-compromise assertions.
- [ ] No unsolicited CVE assignment request, CVSS score, historical CVE comparison, or CWE.
- [ ] No attachment by default; offer details privately on request.
- [ ] Exact approved credit and closing; no redundant email address in signature.
- [ ] Compare against latest approved template, not earlier AI output.
- [ ] User must review in mail app and personally send; no direct send action.
- [ ] If user approves a reusable improvement, update rules and generic changelog; preserve embargo.
