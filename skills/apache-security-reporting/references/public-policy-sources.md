# Official policy sources

Policy checkpoint: 2026-11-07. Re-open these official pages when making current procedural claims. These are documented rules and guidance, not guarantees about any individual report.

| Source | Use | Qualification |
| --- | --- | --- |
| https://security.apache.org/report-code/ | Reporting requirements, private handling, security-model analysis, initial credit information | Tool output needs additional analysis; do not infer a blanket ban on AI assistance. Later credit changes/additions may not be honored. |
| https://www.apache.org/security/committers.html | ASF default acknowledgment, investigation, acceptance/rejection, CVE, remediation and announcement process | Project-specific processes may differ. ASF coordinates; distinguish screening from the project's later investigation. |
| https://cwiki.apache.org/confluence/spaces/SECURITY/pages/327977431/How+to+publish+an+advisory | Record lifecycle, multiple independent reporters, public-fix credit boundary | The credit guidance permits multiple reporters; after a publicly committed fix, later duplicate reporters need not be credited. | https://cloudstack.apache.org/security/ | A publicly documented project-specific reporting and response process | Publicly available project guidance, not an indication of any private finding. |
| https://cwiki.apache.org/confluence/spaces/CLOUDSTACK/pages/30147363/Security+response+procedure | Public example of a project template accepting a duplicate and adding its reporter to an existing CVE credit list | Apply only as that project's published workflow; a template is not an individual acceptance or credit decision. |
| https://www.cve.org/ResourcesSupport/AllResources/CNARules/ | Current CNA rules, updates to records and optional credit fields | Locate the currently applicable version. Optional structured credit is distinct from mandatory vulnerability description content. |

## Source handling
- Prefer current official policy and actual patch contents over secondary summaries.
- Attribute any quoted policy precisely and keep quotations short.
- If a policy page or official record cannot be read, report the access limitation. Do not infer a record's state from a failed request.
- Record verified official record status separately from public search availability.
- Use only officially disclosed examples, or entirely invented examples. A privately received identifier or report reference is not a public example.
- Do not include private case details to explain why a source was added.
